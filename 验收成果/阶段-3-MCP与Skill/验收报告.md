# 阶段三验收报告

## 阶段范围

仅实现《JudgeFlow-开发顺序.md》的“阶段 3：五个 MCP 工具与四个 Skill”。本阶段未新增数据库表或迁移，未实现 FastAPI、HTTP API、Agent、AgentTeams、Matrix、前端、Docker、RAG、消息队列、额外数据库、安全 guard，也未进入阶段四。

## 完成内容

- 基于官方 Python MCP SDK 实现一个本地 stdio MCP Server，严格只注册 `work_order.get`、`context.get`、`evidence.search`、`artifact.put`、`replay.execute` 五个工具；
- MCP Server 启动时通过必填 `JUDGEFLOW_CONSUMER` 绑定可信执行者；五个工具的 MCP input Schema 均不暴露 `consumer`，服务端再次校验 assignee、WorkOrder、run 和 trace；
- `context.get` 只解析 WorkOrder `input_refs`明确授权的材料；Case 和 PolicyEvolution 可读取并按哈希验真锁定 Policy DSL；
- 申诉上下文仅允许原案冻结快照和 `allowed_evidence_ids` 白名单内新证据。锁定规则只从 `original_case_snapshot.policy_snapshot` 解析，按冻结的 policy ID、version 和 content hash 验真，不回退读取实时或新版规则；
- 归因和规则编写上下文对固定回放集过滤 `SCORING`，只暴露 `TRIGGER` 与 `DRAFTING`；
- `evidence.search` 仅使用 `fixtures/evidence/search_results.json`，区分成功、`NOT_FOUND`、`INCOMPLETE_DATA` 和 `TIMEOUT`，不把工具失败解释成无数据；
- `artifact.put` 直接委托阶段二 `JudgeFlowKernel.accept_artifact()`，复用阶段一 `ArtifactEnvelope` 及各 payload Schema，保持类型、run、trace、执行者、幂等与冲突语义；
- `replay.execute` 只委托阶段二 `JudgeFlowKernel.execute_replay()` 和固定 Python 回放器，规则、数据集与输入均受 WorkOrder 引用限制；
- `artifact.put` 和 `replay.execute` 以工具调用为事务边界：成功 commit，失败 rollback，产物与回放结果对第二 Session 可见；
- 实现 `case-investigation`、`case-deliberation`、`policy-evolution`、`case-replay` 四个最小 Skill，每个均包含 `SKILL.md` 及成功、缺失信息、工具失败三类 JSON 样例；
- MCP 不提供状态迁移、Human 审批、处罚或规则发布工具。

## 测试与结果

```bash
UV_CACHE_DIR=/tmp/judgeflow-uv-cache \
uv run pytest tests/test_stage3_mcp.py tests/test_stage3_skills.py -ra --disable-warnings
```

结果：`9 passed`。

全量回归（阶段一、阶段二和阶段三）：

```bash

uv run pytest -ra --disable-warnings
```

结果：`98 passed, 1 skipped`。唯一跳过项是阶段二既有的 PostgreSQL 在线空库迁移测试，原因是本轮未设置 `TEST_DATABASE_URL`；阶段二报告已保存其在线迁移成功证据。

直接测试覆盖：五个工具均通过 FastMCP `server.call_tool` 真实本地调用；可信执行者绑定及冒充拒绝；申诉冻结快照、锁定规则与新证据白名单；规则作者 `SCORING` 隔离；固定证据查询的四种结果；Artifact Schema、类型、WorkOrder、run、trace、生产者、幂等和冲突；写工具的 commit/rollback 及跨 Session 可见；Python 回放的重复一致；四个 Skill 的三类样例。

## 主 Agent 检查

主 Agent 对代码、权限剪裁、事务边界、工具注册、Skill 文件和范围进行了检查，并独立运行上述阶段三测试与全量回归，结果分别为 `9 passed` 和 `98 passed, 1 skipped`。

主审期间发现并交回原实现 Agent 修复了：申诉恶意 `input_refs` 越权、Artifact 幂等返回语义、五工具 FastMCP 真实调用覆盖、回放重复一致性以及 Artifact 类型与 Schema 负测缺口。

## 独立验收结论

独立验收 Agent 仅读检查并运行测试。首次验收发现可信 consumer 未绑定、锁定 Policy DSL 未完整提供、写工具缺少 commit/rollback 边界、FastMCP 成功路径覆盖不足，以及申诉无法从冻结快照取得锁定规则 DSL。上述问题均由原实现 Agent 返修并经主 Agent 复测。

最终独立复验结论为 `PASS`，确认两轮发现项均已关闭，无剩余阻断问题，建议批准阶段三。
